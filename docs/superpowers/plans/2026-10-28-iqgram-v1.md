# IQGram V1 Implementation Plan

> For agentic workers: use the installed test-driven-development and verification-before-completion workflows while changing IQGram.

**Goal:** Ship an actual runnable IQGram MTProto transfer application for Telegram bot and user accounts.

**Architecture:** IQGram facade and SQLite queue over supported WZGram 3.1.1 client transfer methods. Clear separation of auth, transfer logic and bot controls.

**Tech Stack:** Python >=3.11, WZGram 3.1.1, SQLite, pytest, Docker.

**Spec:** `docs/superpowers/specs/2026-10-28-iqgram-v1-design.md`

## Tasks / verification

- [x] Credential input validation and safe path tests. `tests/test_settings.py`
- [x] Media download/upload API-boundary tests. `tests/test_transfer.py`
- [x] SQLite queue/restart and cancellation tests. `tests/test_queue.py`, `tests/test_cancel.py`
- [x] Bot auth, client isolation tests. `tests/test_bot.py`, `tests/test_client.py`
- [x] CLI, config sample, package, Docker and documentation.
- [ ] Live smoke tests against real Telegram servers (must be run with the owner's credentials on their VPS).
- [ ] Throughput comparison with same file vs WZGram baseline (VPS required).

## Review focus

1. Invalid credentials must error before connecting.
2. Access controls deny unknown user IDs, including blank allowlist.
3. Path traversal must never send arbitrary private files.
4. Restart cannot automatically repeat possibly completed uploads.
5. Cancelled queue entries cannot execute.
